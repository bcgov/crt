## Goals

- Review current (legacy) tool - identify fields that are useful and see what can be eliminated and/or improved on

## Discussion items

- Tender Information - Dates screen:
  - Need for multiple tenders for a project re-iterated from previous meeting
  - Utility of combining the tender details and bid information in one table identified
  - Need for having tender# to be included as part of the tender information identified. It clearly associates various entities and can make searching for details a easier
  - Announcement Value and C-035 value to be kept (these should be reflective of the project value, not individual contracts)
  - The following fields were identified as not useful, by the group:
    - Contract Awarded (Planned/Actual/Value) redundant, as the value will be covered in the row with tender and bid details
    - Announcement dates
    - Construction all fields
    - Completion all fields
- Ratios screen -
  - Discussion started but did not go into any detail, running short on time
    - Need for Structure number identified

### Highlights from first review meeting - 2020-11-30 (2 hr)

- Status screen:
  - Differentiate between detailed and public facing project descriptions. Detailed technical description will be captured under Project Scope, and the public facing description will be captured under Project Description (can be found on the Tender screen)
  - Some clear definitions needed to clearly explain some on screen fields - such as Capital Index, and Is the project Active check box - possibly improve on the labels of drop down values for clarity.
  - Group did not find the following fields as useful and would like to remove them/identify some other way:
    - Current Phase (on header) - makes more sense to interpret from the financial planning section,
    - FY for which project is tendered - redundant, covered in tenders section
    - Is the project announced check box - redundant, can be interpreted from tenders section
  - Financial planning and Accomplishment - group generally agreed with the fields available
    - Remove the calculated field - Total project estimates (currently this may not be an accurate representation of the project estimate, because depending on "Type" column in financial planning some of the $values should not be added)
  - For the new application - group fields together the way they would logically - e.g. Project Number, Project Name, Project Description, Project Scope should be all together.
- Tender Information - Dates screen:
  - Projects may have multiple tenders - that can not be captured at this point of time without overwriting old information.
